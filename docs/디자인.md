# 디자인

## 목표

메인 화면에서 사용자가 차량과 서킷의 특성을 비교한 뒤 확신을 가지고 레이스를 시작할 수 있도록 정보 구조를 개선한다. 화면 순서는 기존의 자연스러운 흐름인 `차량 → 서킷 → 레이스 설정`을 유지한다.

## 전체 구조

```text
[헤더 / 현재 단계]

1. 차량 선택
┌─────────────────────────┬──────────────────┐
│ 실제 차량 카드 목록      │ 선택 차량 설명   │
│ 2~4열 비교               │ 드라이버         │
│                          │ 핵심 스탯 4개    │
│                          │ 서킷 추천 이유   │
└─────────────────────────┴──────────────────┘

2. 서킷 선택
┌────────────────────────────────────────────┐
│ 선택 서킷 맵 + 설명 + 난이도 + 특징        │
└────────────────────────────────────────────┘
[난이도/성격 필터]                    [정렬]
[전체 서킷 카드 그리드]

3. 레이스 설정
[모드] [AI] [랩] [날씨] [타이어]

[최종 선택 요약]                              [출발]
```

## 1. 차량 선택

### 차량 카드 영역

- 데스크톱에서는 왼쪽에 3~4열 카드 그리드를 배치한다.
- 현재 게임에서 사용하는 실제 차량 렌더 이미지를 유지한다.
- 카드에는 팀명과 핵심 강점 두 개까지만 표시한다.
- 선택 상태는 팀 컬러 테두리와 명확한 배경 변화로 표현한다.
- 장식적인 수치나 중복 설명은 카드에서 제거한다.

### 선택 차량 상세 영역

- 데스크톱에서는 카드 목록 오른쪽에 배치한다.
- 차량명, 드라이버, 최고속도와 출력 등 기본 제원을 제공한다.
- 파워, 고속 코너, 트랙션, 타이어 관리 등 핵심 스탯 네 개만 표시한다.
- 선택한 서킷과의 관계는 임의의 점수 대신 근거가 드러나는 문장으로 표현한다.
  - 좋은 예: `추천 이유: 고속 코너 성능과 타이어 관리`
  - 피해야 할 예: `스즈카 궁합 92점`
- 모바일에서는 상세 패널을 목록보다 먼저 보여주지 않는다. 선택한 카드 바로 아래에 펼치거나 하단 시트로 표시한다.

## 2. 서킷 선택

### 선택 서킷 상세

- 서킷 카드 목록 위에 가로형 상세 패널을 배치한다.
- 패널 높이는 데스크톱 기준 약 160~180px로 제한한다.
- 다음 정보를 제공한다.
  - 트랙 윤곽
  - 서킷명과 국가 코드
  - 한 문장의 주행 특징
  - 거리와 코너 수
  - 텍스트가 포함된 난이도 (`고급 5/5`)
  - 핵심 태그 2~3개
- 난이도를 색이나 점만으로 전달하지 않는다.

### 탐색과 비교

- 24개 서킷은 숨기지 않고 전체 카드 그리드로 제공한다.
- 각 카드에는 작은 트랙 윤곽을 유지해 시각적으로 구분할 수 있게 한다.
- 필터와 정렬을 별개의 UI로 구분한다.

필터:

- 난이도: 입문, 중급, 고급 중 하나
- 성격: 고속, 시가지, 테크니컬, 고저차 등 복수 선택 가능

정렬:

- 캘린더순
- 난이도 낮은순
- 거리 짧은순
- 거리 긴순
- 코너 많은순

선택한 서킷은 정렬이나 필터 변경 후에도 유지하며, 필터 결과에서 제외되면 사용자에게 명확히 안내한다.

## 3. 레이스 설정

- 자주 확인하는 모드, AI, 랩 수, 날씨, 타이어를 한 영역에 배치한다.
- 각 항목이 단순 정보인지 변경 가능한 버튼인지 시각적으로 명확히 구분한다.
- 선택된 값은 테두리, 배경, 체크 표시 중 두 가지 이상의 단서로 표현한다.
- 고급 설정은 기본 화면을 복잡하게 만들지 않도록 접힌 영역으로 제공한다.

## 하단 요약과 출발

- 현재 차량, 서킷, AI, 참가 대수, 랩 수와 날씨를 한 줄로 요약한다.
- 출발 버튼은 화면에서 유일한 최우선 행동으로 표현한다.
- 필수 선택이 누락되면 출발 버튼을 비활성화하고 누락된 단계로 이동할 수 있게 한다.
- 모바일에서는 요약과 출발 버튼이 조작 영역을 가리지 않도록 높이를 최소화한다.

## 반응형 원칙

### 데스크톱

- 차량 목록과 상세 설명을 좌우로 배치한다.
- 서킷 상세는 목록 위에서 전체 폭을 사용한다.
- 서킷 카드는 화면 폭에 따라 4~6열로 표시한다.

### 태블릿

- 차량 상세를 카드 목록 위 또는 선택 카드 아래로 이동한다.
- 서킷 카드는 3열을 기본으로 한다.
- 필터는 줄바꿈을 허용하고 정렬은 별도의 선택 상자로 유지한다.

### 모바일

- 차량 카드는 2열로 표시한다.
- 차량 상세는 선택 카드 아래에 인라인으로 펼친다.
- 서킷 상세에서는 큰 트랙 이미지를 축소하거나 생략하되 설명과 난이도는 유지한다.
- 서킷 카드는 2열로 표시한다.
- 완료한 단계는 접을 수 있게 해 긴 스크롤을 줄인다.

## 시각 디자인 원칙

- 어두운 배경과 밝은 텍스트를 기본으로 하되 충분한 명도 대비를 확보한다.
- 빨간색은 현재 선택, 핵심 상태와 출발 버튼에만 사용한다.
- 팀 컬러는 차량 선택 상태와 일부 강조 요소에 제한한다.
- 카드 테두리와 그림자는 최소화하고 간격과 배경 명도로 계층을 구분한다.
- 실제 차량 이미지와 트랙 윤곽을 핵심 시각 요소로 사용한다.
- 사선 구분선과 짧은 전환 애니메이션으로 레이싱 게임의 속도감을 더하되 반복 애니메이션은 피한다.

## 접근성

- 모든 카드와 필터는 키보드로 선택할 수 있어야 한다.
- 선택 상태를 색상만으로 전달하지 않는다.
- 난이도는 `5/5`와 같은 텍스트를 함께 제공한다.
- 긴 팀명과 서킷명은 말줄임 처리하되 전체 이름을 확인할 방법을 제공한다.
- 애니메이션 감소 설정을 사용하는 환경에서는 전환 효과를 최소화한다.
- 터치 영역은 최소 44px을 확보한다.

## 구현 우선순위

1. 차량 카드와 오른쪽 상세 패널 구성
2. 서킷 상세 패널을 카드 목록 위로 이동
3. 실제 차량 렌더와 트랙 윤곽 유지
4. 서킷 필터와 정렬 기능 분리
5. 레이스 설정의 선택 상태와 편집 가능성 명확화
6. 모바일 차량 상세 표시 방식 개선
7. 완료 단계 접기와 단계 간 빠른 이동

## 최종 판단

핵심 구조는 `비교 영역 + 선택 상세 영역`의 마스터·디테일 패턴을 따른다. 사용자가 카드만 보고 추측하지 않도록 선택 근거를 가까이 제공하면서도, 한 카드 안에 모든 정보를 넣어 화면이 복잡해지는 문제를 피한다. 구현 시에는 실제 차량 렌더와 트랙 윤곽을 유지하고, 모바일에서 상세 정보의 위치가 선택 흐름을 방해하지 않도록 하는 것이 가장 중요하다.
